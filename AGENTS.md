## Partners
- All separate payment types share a hydration-gated form with explicit non-native submission and visible request feedback, so early clicks cannot leak contact details into a GET URL.
- Separate payment pages derive their Stripe environment from the build's managed publishable token and reject mismatched inputs; service-only environment-scoped catalog/orders and atomic reservations isolate test records and capacity from live without changing Shopify or free Saturday RSVPs.
- Payment administration reuses the confirmed-email organizer allowlist; private package expiration disables its capability token through a server-authorized action so new checkouts fail closed.
- Hat delivery/tax options share one tested helper; persist collected shipping addresses to the Stripe Customer for correct repeat-checkout tax location, and never bypass a missing tax head-office address.
- Partner administration reuses verified existing admin-email access at the server boundary; partner tables remain service-only and public reads use a narrowly projected approved-only database function.
- Partner submissions reuse partner_inquiries with additive source, city and status fields; the new intake sends no messages and applies a database-enforced daily email limit without changing legacy intake.
- Partner logos use private partner-logos storage with server-authorized uploads and approved-only signed public display URLs because workspace policy blocks public buckets; preserve their aspect ratio and original colors.
- Event pages keep all logistics in one config module under src/lib/events/ and store signups in event_rsvps keyed by event slug + email (service-only); keeps Saturday RSVPs untouched.

## Saturday Soundtrack
- RSVPs carry one optional `song` plus `song_credit_ok`; credit is only stored with a song. Public run reports show names solely from the manually curated `soundtrack.credits` in src/content/run-reports.ts, generated by /admin/soundtrack, which never sends more than a first name to the browser.
- Runner reviews live in service-only runner_reviews; public reads go through a server function that returns approved rows with first name only, and moderation reuses the admin email allowlist.
- The site theme is light: page surfaces use bg-background/text-foreground tokens and baby blue is reserved for fills, borders and highlights; never use it for small essential text on white.
